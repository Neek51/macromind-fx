PART 1: WHAT IS GIT? WHAT IS GITHUB? WHAT IS GH?
================================================================

--- GIT ---
Git is a tool installed on your computer that tracks changes in your code.
Think of it like "save points" in a video game — you can save your progress,
see history of all changes, and go back to any previous save point if needed.

  - Git works OFFLINE (no internet needed)
  - Git runs on YOUR computer
  - Git is the "engine" that tracks file changes

--- GITHUB ---
GitHub is a WEBSITE (github.com) where you store your code online.
Think of it like Google Drive or Dropbox but for code.

  - GitHub needs internet
  - GitHub is in the CLOUD (website)
  - GitHub is where others can see, download, and contribute to your code
  - Your repo URL: https://github.com/Neek51/macromind-fx

--- GH (GitHub CLI) ---
`gh` is a command-line tool that lets you interact with GitHub from terminal
WITHOUT opening a browser. It handles login automatically so you don't
need to type username/password every time you push.

  - `gh auth login`     → Login to GitHub (you already did this ✅)
  - `gh repo create`    → Create a new repo on GitHub
  - `gh repo view --web`→ Open your repo in browser
  - `gh repo list`      → List all your repos

PART 3: THE 3-COMMAND WORKFLOW (Use This Daily)
================================================================

Every time you make changes to your project, do these 3 steps:

---

STEP 1: STAGE (put changes in the "box")
---
  git add .

  What it does: Prepares ALL changed files for commit
  The "." means "everything in this folder"
  Files in .gitignore are automatically skipped
  Analogy: Packing items into a shipping box

  Stage specific files only:
  git add src/app/page.tsx
  git add src/app/outlook/page.tsx src/app/types.ts

---

STEP 2: COMMIT (seal the box with a label)
---
  git commit -m "Describe what you changed here"

  What it does: Creates a permanent "save point" with a message
  The -m flag means "message" (the text in quotes)
  Write WHAT and WHY you changed something
  Analogy: Sealing the box and writing a label on it

  Good commit messages:
  git commit -m "Add price alert notification sound"
  git commit -m "Fix chart not loading on mobile"
  git commit -m "Update currency strength colors in dark mode"

  Bad commit messages (don't do this):
  git commit -m "stuff"
  git commit -m "changes"
  git commit -m "update"

---

STEP 3: PUSH (ship the box to GitHub)
---
  git push

  What it does: Uploads your commits to GitHub
  First time pushing a new branch: git push -u origin main
  After that, just: git push
  Analogy: Shipping the sealed box to the cloud warehouse

---

FULL EXAMPLE (copy-paste this workflow):

  cd /home/nisarg/Desktop/ideas/macromind-fx
  git add .
  git commit -m "Add new feature / fix bug / update docs"
  git push

PART 4: ESSENTIAL COMMANDS (Cheat Sheet)
================================================================

--- CHECK STATUS (what changed?) ---
  git status

  Shows:
  - Modified files (changed but not staged)
  - Staged files (ready to commit)
  - Untracked files (new files git doesn't know about)

  Short version:
  git status -s

--- SEE CHANGES (what exactly changed?) ---
  git diff

  Shows line-by-line changes in unstaged files
  Green lines = added
  Red lines = removed

  See staged changes only:
  git diff --staged

--- VIEW HISTORY (all past commits) ---
  git log

  Shows all commits with: hash, author, date, message
  Short one-line version:
  git log --oneline

  Last 5 commits only:
  git log --oneline -5

--- SEE WHAT BRANCH YOU'RE ON ---
  git branch

  Current branch has a * next to it
  Your main branch is called: main

--- CHECK REMOTE (where is code stored?) ---
  git remote -v

  Shows where your code is linked (origin = GitHub URL)

PART 5: PULL (Download Latest from GitHub)
================================================================

  git pull

  What it does: Downloads latest changes from GitHub to your computer
  Use this when:
  - You made changes on GitHub website directly
  - Someone else pushed changes to your repo
  - You're working from a different computer
  Analogy: Receiving new boxes from the cloud warehouse

PART 7: UNDO / FIX MISTAKES
================================================================

--- Undo changes in a file (before staging) ---
  git restore filename.tsx

  Warning: This deletes your changes! Can't undo after this.

--- Unstage a file (undo git add) ---
  git restore --staged filename.tsx

  The file goes back to "modified" but changes are kept.

--- Undo last commit (but keep your changes) ---
  git reset HEAD~1

  Your changes are NOT deleted — they go back to "unstaged"
  You can then fix and re-commit.

--- Change your last commit message ---
  git commit --amend -m "New better message"

  Only works if you haven't pushed yet!

--- Danger: Undo last commit AND delete changes ---
  git reset --hard HEAD~1

  WARNING: This permanently deletes your changes. Use with caution!

================================================================

The .gitignore file tells git which files to SKIP. Your project has:

  .env*          → Environment variables (API keys — SECRET!)
  node_modules/  → Downloaded dependencies (too big, not needed on GitHub)
  .next/        → Build output (generated, not source code)
  .qwen/        → Qwen Code internal config
  resume.text    → Personal session token
  todo.text      → Personal notes

If you create a new file that should NOT be on GitHub, add it to .gitignore:
  echo "secret-file.txt" >> .gitignore

PART 9: GH CLI COMMANDS (GitHub from Terminal)
================================================================

--- Login (you already did this ✅) ---
  gh auth login

--- Check if you're logged in ---
  gh auth status

--- Create a new repo ---
  gh repo create my-new-project --public --source=. --remote=origin
  gh repo create my-private-project --private --source=. --remote=origin

--- Open your repo in browser ---
  gh repo view --web

--- List all your repos ---
  gh repo list

--- View a specific repo info ---
  gh repo view Neek51/macromind-fx

PART 11: GIT VOCABULARY (Terms to Know)
================================================================

  Repository (repo)  → A project folder tracked by git
  Commit             → A "save point" with a message
  Stage (index)      → Preparing files for commit (the "box")
  Push               → Upload commits to GitHub
  Pull               → Download latest from GitHub
  Clone              → Download a full copy of a repo
  Branch             → A separate line of work (you use: main)
  Remote             → The GitHub URL linked to your local repo
  Origin             → The default name for your remote (GitHub URL)
  HEAD              → The current position (latest commit on current branch)
  .gitignore        → File listing what git should NOT track
  Fork              → A personal copy of someone else's repo
  Merge             → Combine changes from two branches
